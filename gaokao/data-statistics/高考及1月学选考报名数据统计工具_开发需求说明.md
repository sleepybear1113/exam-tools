# 高考及1月学选考报名数据统计工具——开发需求说明

> **文档用途：** 将本文档整体交给 AI Agent，要求其直接实现一个可在浏览器本地运行的 HTML 数据统计工具。
>
> **开发方式：** 原生 HTML + CSS + JavaScript + Vue CDN，不使用 Node.js、npm、Vite、Webpack 或其他构建工具。所有业务数据均在浏览器本地解析和计算，不上传服务器。
>
> **本期实现范围：** 高考报名信息、高考报名缴费信息、1月学选考报名信息。1月学选考报名缴费信息暂不处理。
> **已确认的关键业务口径：** `CJTZSCS_` 仅当值为 `1` 时计入特招生测试人数；高考报名与缴费交叉统计时，艺术类未缴费只影响对应术科人数，不影响符合普通类总人数纳入条件的考生总人数；传媒缴费仅对应 `36` 播音与主持类；`39` 戏曲类省际联考不需要匹配缴费项目，只要报名了且考生符合总人数纳入条件，就计入戏曲类人数。

---

## 一、开发目标与总体要求

开发一个面向考试报名数据的本地统计页面。用户将 Excel 文件拖入对应文件区域，程序读取文件、过滤审核状态、标准化字段、根据报名点及县区映射表进行分组，并按照用户选择的统计类型生成多个 HTML 表格。

### 1.1 本期支持的文件类型

用户描述中提到“3个 Excel 文件”，实际列出了以下 4 种文件类型。本期实现前 3 种：

| 文件类型 | 常见扩展名 | 本期是否处理 | 用途 |
|---|---|---:|---|
| 高考报名信息 | `.xlsx` | 是 | 高考报名人数、术科分类人数、特招生测试人数 |
| 高考报名缴费信息 | `.xls` | 是 | 按报名点统计各项目已缴费/未缴费人数，并与高考报名信息交叉比对 |
| 1月学选考报名信息 | `.xlsx` | 是 | 统计语文、数学、外语及各选考/学考科目人数 |
| 1月学选考报名缴费信息 | `.xls` | 否 | 本期不上传、不读取、不参与统计，预留后续扩展位置即可 |

页面只需要前三种文件的上传区域。不要为暂不处理的 1 月学选考缴费文件编写解析和统计逻辑。

### 1.2 核心原则

1. 文件必须拖入对应类型的区域，不允许将一个文件随意拖到页面任意位置后自动猜测类型。每个区域同时提供“选择文件”按钮。
2. 每个上传区域独立维护文件状态，可以单独替换、移除和重新读取。
3. 允许只上传一种文件，也允许同时上传两种或三种文件。
4. 统计类型由用户手动勾选，点击“生成统计”后执行。不得因为上传了某个文件就自动生成所有报表。
5. 所有报名统计先执行审核状态过滤，再进行去重、缴费匹配、分组与统计。
6. 身份证号码是人员去重及跨文件关联的唯一主键，不得使用姓名作为关联主键。
7. 所有统计结果必须有明确的统计口径，不能直接按 Excel 行数累加。
8. 对无法识别的字段、报名点、项目代码、缴费状态和重复数据，应给出警告或异常明细，不能静默忽略。
9. 页面不上传任何 Excel 数据，不调用业务后端接口。浏览器内存中处理原始数据。
10. 不需要登录、数据库、服务端、Node.js 或复杂框架。

## 二、技术架构与文件组织

### 2.1 技术选型

- Vue：Vue 3.5.44 Global Production 版本，使用 `Vue` 全局变量。
- Excel：SheetJS Community Edition 0.20.3 **完整版** `xlsx.full.min.js`。
- HTML：原生 HTML5。
- CSS：独立 CSS 文件，不使用 Bootstrap、Tailwind 等 CSS 框架。
- JavaScript：原生 JavaScript，使用 Vue 3 CDN 版本管理页面状态。
- 浏览器：以当前版本 Chrome、Edge 为目标。

**重要：不要使用 `xlsx.mini.min.js`。** SheetJS Mini Build 不支持传统 `.xls`（BIFF）格式，本项目必须读取 `.xls` 和 `.xlsx`，因此必须统一使用完整版 `xlsx.full.min.js`。不需要再引入另一个专门读取 `.xls` 的库。

建议 CDN 地址：

```html
<script src="https://cdn.jsdelivr.net/npm/vue@3.5.44/dist/vue.global.prod.js"></script>
<script src="https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js"></script>
```

如需离线使用，可以将上述两个文件下载到项目的 `vendor` 目录，再改用本地相对路径。不要将 CDN 地址写死在业务 JS 中。

如果开发环境中现有 Vue 文件的实际名称是用户指定的 `vue.3.5.44.global.prod.prod.js`，可以保留该文件名并在 HTML 中按实际路径引用；上述 `vue.global.prod.js` 是 Vue 3.5.44 Global Production 构建的标准文件名，二者只要内容确实对应 Vue 3.5.44 即可。

### 2.2 建议目录结构

```text
项目目录/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  ├─ app.js                  # Vue 页面、上传交互、统计类型选择、结果渲染
│  ├─ excel-reader.js         # Excel 文件读取、工作表选择、表头识别
│  ├─ data-normalizer.js      # 字段标准化、审核状态、身份证、报名点代码处理
│  ├─ statistics-gaokao.js   # 高考报名统计及缴费交叉过滤
│  ├─ statistics-payment.js  # 高考缴费独立统计
│  └─ statistics-january.js  # 1月学选考统计
└─ vendor/
   ├─ vue.global.prod.js
   └─ xlsx.full.min.js
```

目录名称可以调整，但必须保持 HTML、CSS、JS 分文件，不要把所有代码堆在一个 HTML 文件里。

### 2.3 不使用 ES Module 的原因

本工具应尽量支持直接双击 `index.html`，以 `file://` 方式运行。业务 JS 使用普通 `<script>` 按顺序加载，通过 `window` 下的命名空间暴露模块方法，不使用 `type="module"` 和 `import/export`，避免本地文件环境下的模块跨域限制。

推荐加载顺序：

```html
<script src="./vendor/vue.global.prod.js"></script>
<script src="./vendor/xlsx.full.min.js"></script>
<script src="./js/excel-reader.js"></script>
<script src="./js/data-normalizer.js"></script>
<script src="./js/statistics-gaokao.js"></script>
<script src="./js/statistics-payment.js"></script>
<script src="./js/statistics-january.js"></script>
<script src="./js/app.js"></script>
```

如果采用 CDN，则只替换 Vue 和 SheetJS 的 `src`，其余要求不变。

## 三、页面布局与交互设计

采用单页面、纵向分区布局。桌面端优先，页面宽度充分利用浏览器可用空间。

### 3.1 页面整体布局

从上到下依次为：

1. 页面标题与数据安全提示。
2. Excel 文件上传区域。
3. 报名点及县区映射配置区域。
4. 统计类型选择区域。
5. 统计操作区域。
6. 数据校验及异常提示区域。
7. 统计结果区域。

### 3.2 文件上传区域

使用三个独立的上传卡片，建议桌面端横向排列，窄屏时自动换行。

#### 上传卡片 A：高考报名信息

- 标题：高考报名信息（`.xlsx`）。
- 主要提示：将高考报名信息 Excel 文件拖动到此区域。
- 接受扩展名：`.xlsx`。
- 提供“选择文件”按钮。
- 读取成功后显示：文件名、文件大小、工作表名称、识别到的表头行、有效数据行数、审核通过人数、重复身份证数。

#### 上传卡片 B：高考报名缴费信息

- 标题：高考报名缴费信息（`.xls`）。
- 主要提示：将高考报名缴费 Excel 文件拖动到此区域。
- 接受扩展名：`.xls`；可以兼容 `.xlsx`，但不必主动提示。
- 提供“选择文件”按钮。
- 读取成功后显示：文件名、文件大小、工作表名称、表头行、有效数据行数、已识别报名点数、无法解析缴款单号行数。

#### 上传卡片 C：1月学选考报名信息

- 标题：1月学选考报名信息（`.xlsx`）。
- 主要提示：将 1 月学选考报名信息 Excel 文件拖动到此区域。
- 接受扩展名：`.xlsx`。
- 提供“选择文件”按钮。
- 读取成功后显示：文件名、文件大小、工作表名称、表头行、有效数据行数、审核通过人数、重复身份证数。

#### 上传交互要求

- 每个卡片有独立的 `input[type=file]`，设置正确的 `accept`。
- 拖动进入对应区域时显示高亮状态；拖动离开时恢复；放下后只读取该区域的文件。
- 必须阻止 `dragover`、`drop` 默认行为，防止浏览器直接打开文件。
- 文件必须放在正确卡片。将 `.xls` 拖入高考报名信息卡片时，应提示文件类型不匹配，不允许误解析。
- 选择文件按钮与拖放行为共用同一套校验和读取逻辑。
- 同一上传卡片再次上传文件时，询问或直接替换旧文件均可，但必须有明确的替换提示；不得将新旧数据合并。
- 每张卡片有“移除文件”按钮。移除后，该文件对应的统计类型不可选或变为不可用，并清空该文件的解析数据。
- 显示读取中、读取成功、读取失败状态。
- 读取失败时显示具体原因，例如文件格式不正确、未找到工作表、未识别到表头、缺少必需字段等。
- 不要仅依赖文件 MIME Type 判断格式，以扩展名和实际解析结果共同校验。

### 3.3 报名点与县区映射配置

提供两个独立的映射配置面板，可折叠。

#### A. 报名点映射

用途：报名点代码映射为报名点名称。

数据结构：

```json
{
  "报名点代码1": "报名点名称1",
  "报名点代码2": "报名点名称2"
}
```

#### B. 县区映射

用途：从报名点代码中提取县区代码，再映射为县区名称。

数据结构：

```json
{
  "县区代码1": "县区名称1",
  "县区代码2": "县区名称2"
}
```

#### UI 要求

- 建议使用可编辑的两列表格，而不是要求普通用户直接手写 JSON。
- 两列分别是“代码”和“名称”，支持新增行、删除行、编辑值。
- 支持从剪贴板粘贴两列 TSV 数据。
- 可提供“导入 JSON”和“导出 JSON”辅助功能，但不是必须。
- 代码统一按字符串处理，不能因为是数字而丢失前导零。
- 对重复代码提示冲突；同一个代码只允许有一个名称。
- 映射表保存在 `localStorage`，仅保存报名点名称映射和县区名称映射，不保存身份证、姓名、原始 Excel 内容或统计明细。
- 初次进入时映射表为空，不得自行编造嘉兴市县区或报名点代码及名称。
- 未配置的报名点，统计结果仍保留该代码，名称显示为“未配置名称”；同时在异常提示中列出未配置代码。
- 未配置的县区，县区名称显示为“未配置名称”。

### 3.4 特招生测试标志

`CJTZSCS_` 的统计规则已经明确：**字段值严格等于 `1` 时计入特招生测试人数**。

实现要求：

- 先将单元格值转换为字符串并去除首尾空格，再判断是否等于字符串 `1`。
- 数值 `1` 和文本 `"1"` 均应识别为命中。
- 其他值（包括空白、`0`、`是`、`Y` 等）均不计入。
- 不提供特招生测试命中值编辑器，不允许用户通过页面将其他值配置为命中值。
- 可以在数据校验区域展示 `CJTZSCS_` 的非空原始取值分布，供人工核查；但这不改变固定统计口径。
- 若字段缺失，则特招生测试人数指标显示为“字段缺失/无法统计”，不能将其默认为 0。

### 3.5 统计类型选择

使用复选框，允许同时勾选多个统计类型。根据上传状态动态启用或禁用。

| 统计类型 | 所需文件 | 说明 |
|---|---|---|
| 高考报名信息统计 | 高考报名信息 | 按报名点及县区统计；若同时上传缴费文件，则自动执行缴费交叉过滤 |
| 高考报名缴费统计 | 高考报名缴费信息 | 按报名点统计总人数及各项目已缴费/未缴费人数 |
| 1月学选考报名统计 | 1月学选考报名信息 | 按报名点及县区统计各科目人数 |

用户可以只选择其中一种，也可以选择多种。

**交叉比对不需要做成一个独立统计类型。** 当用户选择“高考报名信息统计”，并且高考报名缴费文件也已上传时，程序自动使用缴费信息过滤高考报名中的相关人数。若没有缴费文件，则直接统计审核通过的高考报名信息，并在结果上方显示“未提供缴费信息，艺术体育类统计可能包含未缴费考生”的明显提示。

### 3.6 操作按钮

- “生成统计”：只有至少选择一种可用统计类型时才允许点击。
- “清空统计结果”：只清空当前报表，不移除上传文件。
- “重置全部”：清空三个上传文件、统计结果和当前页面数据；映射表默认保留，除非用户在二次确认框中选择同时清空映射。
- 生成过程中显示加载状态，防止重复点击。

### 3.7 结果区域

- 每个统计结果都是独立的 HTML `<table>`，必须有明确标题。
- 每张表上方显示统计类型、数据来源文件名、统计时间、审核过滤口径和缴费过滤口径。
- 每张表都应有表头、数据行和合计行（适用时）。
- 宽表格使用独立的横向滚动容器，不得使整个页面横向溢出。
- 表头可以 sticky；数字列右对齐，代码和名称列左对齐或居中。
- 数字统一使用整数格式，不显示小数或科学计数法。
- 结果表格按县区代码、报名点代码排序；县区汇总按县区代码排序。
- 当没有数据时显示空状态，不生成看似有效的全零统计。
- 不要求本期实现图表；统计结果以 HTML 表格为主。
- 本期不强制要求导出 Excel/CSV，优先保证统计准确性。

## 四、Excel 读取与表头识别

### 4.1 读取方式

通过浏览器 File API 读取用户本地文件：

1. 使用 `file.arrayBuffer()` 获取文件二进制数据。
2. 使用 `XLSX.read(arrayBuffer, { type: 'array', cellDates: false })` 解析工作簿。
3. 从 `workbook.SheetNames` 获取工作表名称。
4. 检查各工作表的前若干行，寻找符合对应文件类型的表头行。
5. 表头识别成功后，将数据行转换为统一对象结构。

不要使用 `XLSX.readFile()`，它是文件系统路径读取接口，不适用于浏览器中的用户本地文件。

### 4.2 工作表选择

- 默认自动扫描所有工作表，选择第一个满足对应文件类型必需字段的工作表。
- 如果只有一个工作表符合要求，自动使用该工作表。
- 如果多个工作表符合要求，显示工作表选择框，让用户选择。
- 如果没有工作表符合要求，提示未识别到所需表头，并列出实际工作表名称。
- 表头行不一定是第一行，建议扫描前 20 行；识别到后将下一行作为数据起始行。

### 4.3 表头规范化

- 去除字段前后空格、全角空格及 BOM 字符。
- 不要直接依赖列序号，必须按表头名称定位列。
- 高考报名信息中带下划线解释的字段，按下划线前的字段代码匹配。例如 `SHZT_审核状态`、`BJ_班级`、`SFZH_身份证号码`。匹配时允许后缀解释文字不同，但字段代码必须准确。
- 1月学选考字段按用户提供的固定列名匹配。
- 缴费文件字段按给定列名匹配。
- 对缺失字段区分“必要字段缺失”和“可选字段缺失”。必要字段缺失时拒绝生成该类统计；可选字段缺失时允许生成，但相关指标显示为不可用并给出警告。

### 4.4 数据读取注意事项

- 身份证号码、报名点代码、缴款单号、项目编号一律按字符串处理。
- 不得对身份证号码使用 `Number()`、`parseInt()` 等数值转换。
- 使用 `raw: true` 或直接读取单元格原始值，避免将身份证等文本擅自格式化。
- Excel 如果已经把 18 位身份证号码保存为数值，可能在 Excel 保存阶段丢失精度。程序不能可靠还原。发现身份证号码来自数值单元格且超过 JavaScript 安全整数范围时，应标记为“身份证号码可能已损坏”，该行不参与跨文件匹配，并显示异常数量。
- 不要将身份证号码转成科学计数法字符串后参与关联。
- 对文本型身份证号码，去除首尾空格，将末尾 `x` 统一转为大写 `X`；不要删除身份证内部字符。
- 缴款单号同样要避免数值精度丢失，因为需要按固定位置截取字符。
- 读取时不修改原 Excel 文件。

## 五、所有文件共用的数据过滤与规范化规则

### 5.1 审核状态过滤

所有**报名信息文件**均只保留审核状态符合以下条件的记录：

- 数值 `3`；
- 字符串 `"3"`；
- 字符串 `"审核通过"`。

判断前应去除首尾空格，并统一全角/半角空格。

其他审核状态全部过滤掉。空白、待审核、审核不通过等均不得进入统计。

**缴费文件的特殊情况：** 用户提供的高考报名缴费文件字段列表不含 `SHZT`/审核状态字段，因此无法直接对缴费文件本身做审核状态过滤。实现时：

- 如果缴费文件确实没有审核状态列，则不执行该文件的审核过滤；缴费统计根据缴款状态统计。
- 在报名与缴费交叉统计时，先对高考报名信息执行审核状态过滤，再仅对这些审核通过的报名人员进行身份证匹配。
- 如果实际缴费文件中额外存在审核状态列，可以作为可选字段识别，并按同一规则过滤，但不得将其列为必需字段。

### 5.2 身份证号码标准化

定义统一函数 `normalizeIdCard(value)`：

- 空值返回空字符串。
- 转字符串并去除首尾空格。
- 末尾小写 `x` 转大写 `X`。
- 不删除内部字符，不擅自补位，不进行数值转换。
- 空身份证号码的记录不进入按身份证去重的统计，并计入异常数据。

### 5.3 报名点代码标准化

定义统一函数 `normalizeBmdCode(value)`：

- 将值转为字符串并去除首尾空格。
- 如果是纯数字且长度不足 5 位，按 5 位左侧补零处理；如果长度超过 5 位，不截断，标记异常。
- 如果是文本代码，保留原字符，不做数值转换。
- 统计分组时使用标准化后的报名点代码。

### 5.4 报名点与县区名称

- 报名点名称：通过完整报名点代码查询报名点映射表。
- 县区代码：从完整报名点代码中提取**第 2–3 位（按 1 起始位数）**，即 JavaScript `code.slice(1, 3)`。
- 县区名称：通过县区代码查询县区映射表。
- 如果代码长度不足 3 位，县区代码为空，并列入异常。
- 未配置的名称显示“未配置名称”，代码仍然保留。

### 5.5 重复人员处理

所有报名信息统计均以身份证号码为唯一主键。

默认去重规则：

1. 先过滤审核状态，再进行身份证去重。
2. 同一身份证在同一个报名点出现多行：只计 1 人。对于术科或科目字段，可以合并同一身份证记录中的有效类别标记，避免重复行漏计类别。
3. 同一身份证出现在不同报名点：视为报名点冲突，不得在两个报名点重复计数。将该身份证放入异常清单，默认不纳入报名点及县区统计，提示用户检查源数据。
4. 不同身份证即使姓名相同，也分别计数。
5. 姓名只用于展示或异常辅助，不参与主键关联。

缴费文件按“身份证号码 + 项目类别 + 报名点”去重，具体规则见第七节。

## 七、高考报名缴费信息统计

### 7.1 相关字段

缴费 Excel 文件字段如下：

| 字段 | 含义 | 用途 | 是否必要 |
|---|---|---|---:|
| 缴款单号 | 缴款流水/单号 | 提取报名点代码 | 是 |
| 姓名 | 姓名 | 辅助信息 | 否 |
| 证件号码 | 身份证号码 | 人员去重及关联 | 是 |
| 缴款状态 | 缴费状态 | 区分已缴费、未缴费 | 是 |
| 缴款金额 | 缴款金额 | 本期读取备用，不汇总金额 | 否 |
| 项目编号 | 缴费项目编号 | 解析项目类别 | 是 |

本期不按缴款金额汇总。

### 7.2 从缴款单号提取报名点代码

按字符串处理缴款单号，位置按照**从 1 开始计数**：

- 第 18–21 位：报名点代码的后四位。
- 第 22–23 位：用于确定报名点代码的第一位。

第一位映射规则：

| 第 22–23 位解析出的数字 | 报名点代码第一位 |
|---:|---:|
| 0–12（含 12） | `8` |
| 13–50（含 50） | `9` |
| 大于 50 | `7` |
| 非数字或无法解析 | 空，标记异常 |

最终报名点代码：`第一位 + 第18–21位`，通常为 5 位代码。

示意伪代码：

```js
const suffix = orderNo.slice(17, 21);
const indicatorText = orderNo.slice(21, 23);
const indicator = Number(indicatorText);

let first = '';
if (indicatorText !== '' && Number.isFinite(indicator)) {
  if (indicator <= 12) first = '8';
  else if (indicator <= 50) first = '9';
  else first = '7';
}

const bmdCode = first && suffix.length === 4
  ? first + suffix
  : '';
```

校验要求：

- 缴款单号长度不足 23 位，无法按固定位置解析，列入异常数据。
- 第 18–21 位不是 4 位有效字符，列入异常数据。
- 第 22–23 位不是数字，报名点代码为空并列入异常数据。
- 不得把缴款单号转为数值后再截取。
- 同一报名点代码按字符串处理，并使用报名点映射表获取名称。

### 7.3 项目编号解析

项目编号包含下划线 `_`，下划线后部分为项目类别代码，不区分大小写。

建议取最后一个下划线之后的内容作为类别代码，并去除前后空格。若项目编号完全没有下划线或后缀为空，则列入异常。

项目代码映射：

| 类别代码 | 展示名称 |
|---|---|
| `pt` | 普通类 |
| `cm` | 传媒 |
| `ms` | 美术类 |
| `sf` | 书法类 |
| `szby` | 时装表演类 |
| `ty` | 体育类 |
| `wd` | 舞蹈类 |
| `yy` | 音乐类 |

未识别的项目代码不参与已知类别统计，但必须在异常提示中列出原项目编号、未知代码及数量。

### 7.4 缴款状态规范化

| 原始缴款状态 | 统计归类 |
|---|---|
| 已缴款 | 已缴费 |
| 待缴款 | 未缴费 |
| 未缴款 | 未缴费 |
| 空白或其他未知值 | 未知状态，单独列入异常，不擅自归为已缴费或未缴费 |

处理前去除首尾空格。不要把“待缴款”统计成已缴费。

### 7.5 缴费数据去重

- 身份证号码标准化后作为人员主键。
- 统计某个报名点、某个项目类别的人数时，同一身份证号码只计 1 人。
- 同一身份证、同一报名点、同一类别出现多条记录：若其中至少一条为“已缴款”，该身份证在该类别归为已缴费；否则若至少一条为“待缴款”或“未缴款”，归为未缴费；若全为未知状态，则归为未知状态。
- 不得因同一身份证有多条相同项目记录而重复累加。
- 同一身份证、同一类别被解析出不同报名点代码时，列入报名点冲突异常。默认不将该身份证的该类别计入任何一个报名点，避免重复或错分。

### 7.6 缴费统计表（按报名点）

表格标题：**高考报名缴费统计（按报名点）**。

分组字段：提取后的报名点代码。

基础展示列：

- 县区代码；
- 县区名称；
- 报名点代码；
- 报名点名称；
- 总人数。

总人数口径：**普通类（`pt`）项目中出现的去重身份证号码数**，不区分该普通类记录是已缴款还是未缴款。普通类代表该报名点的缴费人员基数。

项目统计列：每个类别分别统计已缴费人数和未缴费人数。

类别列顺序：

1. 普通类；
2. 传媒；
3. 美术类；
4. 书法类；
5. 时装表演类；
6. 体育类；
7. 舞蹈类；
8. 音乐类。

列排列顺序必须是：

- 先排列所有类别的“已缴费”列；
- 再排列所有类别的“未缴费”列。

例如：

```text
普通类_已缴费、传媒_已缴费、美术类_已缴费、书法类_已缴费、
时装表演类_已缴费、体育类_已缴费、舞蹈类_已缴费、音乐类_已缴费、
普通类_未缴费、传媒_未缴费、美术类_未缴费、书法类_未缴费、
时装表演类_未缴费、体育类_未缴费、舞蹈类_未缴费、音乐类_未缴费
```

“待缴款”和“未缴款”统一计入未缴费列。

若某个类别没有任何记录，显示 0，不要省略该类别列。

### 7.7 普通类与其他类别的关系

普通类是所有后续类别的缴费前提。程序在缴费统计中应保留各项目的实际缴款状态统计，同时做业务校验：

- 某身份证的非普通类项目显示已缴款，但该身份证没有普通类已缴款记录时，列为“非普通类已缴费、普通类未缴费/缺失”的异常。
- 不要将这种异常记录从原始缴费状态统计中静默删除；实际缴款记录仍应如实反映在缴费统计表中。
- 在高考报名与缴费交叉统计时，按下一节规定，普通类已缴费是纳入报名总人数及其他类别人数的前提。

### 7.8 关于缴费文件缺失审核状态字段

当前给定缴费文件字段没有审核状态，因此独立缴费统计只能按缴款状态分类。不得虚构审核状态过滤结果。若需要根据审核状态过滤独立缴费表，必须由用户补充实际审核状态字段或明确关联报名文件的方式。

## 八、高考报名信息与缴费信息交叉比对

### 8.1 启用条件

当以下两个文件均成功读取时启用：

- 高考报名信息；
- 高考报名缴费信息。

当用户选择“高考报名信息统计”时，自动使用交叉比对结果生成按报名点表及县区汇总表，不再使用未过滤的原始术科统计结果。

### 8.2 匹配主键及基本规则

- 仅以标准化后的身份证号码作为关联主键。
- 先对高考报名信息执行审核状态过滤，再进行缴费匹配。
- 缴费文件中，只有 `缴款状态 = 已缴款` 才是已缴费记录。
- `待缴款`、`未缴款` 都不能视为已缴费。
- 同一个身份证在同一缴费类别有重复记录时，任意一条为已缴款，即认为该类别已缴费；否则视为未缴费或未知状态。
- 如果某个报名人员在缴费文件中完全找不到任何身份证匹配记录，按用户要求视为已缴费，保留其原有报名信息及术科统计。

### 8.3 报名人员纳入总人数的默认规则

为落实“丢弃未缴费的人”以及“普通类是其他类别缴费前提”的要求，本期建议采用以下默认规则：

| 人员在缴费文件中的情况 | 是否纳入高考报名总人数 | 是否纳入术科类别人数 |
|---|---:|---|
| 完全没有任何该身份证的缴费记录 | 是，视为已缴费 | 是，保留其报名术科 |
| 有缴费记录，普通类 `pt` 已缴款 | 是 | 继续按对应术科类别的缴费情况判断 |
| 有缴费记录，普通类 `pt` 为待缴款或未缴款 | 否 | 否 |
| 有缴费记录，但没有普通类 `pt` 记录 | 否，并列入异常 | 否 |
| 有缴费记录，但普通类状态无法识别 | 否，并列入异常 | 否 |

特别说明（已由业务方确认）：如果某考生普通类 `pt` 已缴款、美术类 `ms` 未缴款，且报名信息中包含 `31` 美术与设计类，则该考生**仍计入高考报名总人数**，但**不计入美术与设计类人数**。其他有独立缴费项目映射的术科同理：术科是否计入只看该类别对应项目的缴费状态，不因该术科未缴费而删除整名考生或影响其总人数。戏曲类 `39` 按第 8.4 节的特殊规则处理，不要求对应缴费项目。

注意：以上“总人数”是交叉过滤后的高考报名人员数，不等同于缴费统计表中普通类的总人数；两者数据来源和统计对象不同。

### 8.4 术科报名与缴费类别的对应关系

交叉比对时，除普通类前置条件外，还应按以下关系判断各术科是否计入高考报名术科统计列：

| 缴费项目类别 | 对应高考报名术科 | 规则 |
|---|---|---|
| `ms` 美术类 | `31` 美术与设计类 | 美术类未缴费，不计该人的美术与设计类人数 |
| `ty` 体育类 | `41` 体育类 | 体育类未缴费，不计该人的体育类人数 |
| `sf` 书法类 | `30` 书法类 | 书法类未缴费，不计该人的书法类人数 |
| `wd` 舞蹈类 | `33` 舞蹈类 | 舞蹈类未缴费，不计该人的舞蹈类人数 |
| `yy` 音乐类 | `32` 音乐类 | 音乐类未缴费，不计该人的音乐类人数 |
| `cm` 传媒 | `36` 播音与主持类 | 传媒缴费只对应播音与主持类（代码 `36`）。传媒类未缴费，不计该人的播音与主持类人数 |
| `szby` 时装表演类 | `34` 表（导）演类 | 时装表演类未缴费，不计该人的表（导）演类人数 |

**戏曲类省际联考（代码 `39`）是明确的例外：不需要对应任何缴费项目。** 只要审核通过的报名记录中包含 `39`，且该考生符合第 8.3 节的高考报名总人数纳入条件，就计入“戏曲类省际联考”人数。无论该身份证是否存在缴费记录，也无论其是否有其他术科缴费记录，都不因缺少戏曲类缴费项目而排除 `39`。不得将其标记为“缺少缴费映射规则”。

### 8.5 传媒缴费的识别

`cm`（传媒）缴费项目**仅对应 `YSTYSK_` 中的 `36`（播音与主持类）**。

实现要求：

- `cm` 已缴费且该考生报名信息包含 `36`，才计入播音与主持类人数。
- `cm` 未缴费，不计入播音与主持类人数。
- 不存在独立的“传媒类”报名术科代码，不应额外识别文本 token `传媒` 或 `传媒类`。
- 不得将 `cm` 映射到其他术科代码。

### 8.6 特招生测试人数

特招生测试人数属于高考报名信息本身的标志统计，不属于艺术体育缴费类别。默认处理：

- 只要人员通过审核，且符合第 8.3 节的人员纳入规则，`CJTZSCS_` 去除首尾空格后严格等于 `1`，就计入特招生测试人数。
- 不额外要求其具有某个艺术体育缴费项目；某个艺术体育类别未缴费，不影响该人员在总人数纳入前提下的特招生测试计数。

### 8.7 交叉比对异常信息

至少记录以下异常：

- 报名人员身份证为空或身份证格式/数值精度异常；
- 报名人员在多个报名点出现；
- 缴费文件身份证为空；
- 缴费单号无法提取报名点；
- 同一身份证同一缴费类别出现多个报名点；
- 普通类缺失或未缴费，但其他类别已缴费；
- 术科类别存在，但缴费类别映射未定义；
- 报名点或县区映射缺失。

异常区可以只显示汇总数量和少量样例；不得在普通提示区域完整展示大量身份证号码。确需展示时，身份证中间部分脱敏。

## 十一、异常提示与数据质量检查

生成统计前和统计后都应执行必要校验。

### 11.1 文件及表头异常

- 文件类型与上传区域不匹配；
- 文件无法解析或已损坏；
- 没有可用工作表；
- 没有识别到表头；
- 缺少必要字段；
- 工作表存在多份候选表头，需要用户选择。

### 11.2 数据异常

- 身份证为空；
- 身份证为数值类型且精度可能丢失；
- 同一身份证对应多个报名点；
- 审核状态未知；
- 术科代码未知；
- 缴款单号长度不足或位置字符异常；
- 项目编号没有下划线或项目代码未知；
- 缴款状态未知；
- 缴费数据同一身份证、同一类别对应多个报名点；
- 非普通类已缴款但普通类未缴款/缺失；
- 外语语种代码未知；
- 科目值不是学考、选考或空白；
- 报名点名称映射缺失；
- 县区名称映射缺失。

### 11.3 异常区域展示

将异常分为“错误”和“警告”：

- **错误：** 影响统计准确性或导致必要字段无法读取。例如缺少身份证列、报名点列、审核状态列。对于受影响的统计类型，禁止生成报表。
- **警告：** 仍可统计，但可能有数据未纳入或映射不完整。例如未知术科代码、报名点名称未配置、未知语种。

每类异常显示数量，并可展开查看样例。身份证号码应默认脱敏，例如 `3304**********1234`。

## 十二、隐私、安全和性能要求

1. 不使用 `fetch`、XHR、后端 API 或第三方云服务上传 Excel 内容。
2. 不将原始 Excel 数据、姓名、身份证号码或统计明细保存到 `localStorage`、`sessionStorage` 或 IndexedDB。
3. 只有报名点映射、县区映射等非个人数据可以保存到 `localStorage`。
4. 页面刷新后，原始文件需要重新上传；不做自动恢复原始数据。
5. 不将文件名、身份证号码、姓名等信息写入远程日志。
6. 统计结果只在当前页面内存中存在，点击“重置全部”或刷新页面后清空。
7. 面对较大 Excel 文件，避免多次重复解析同一文件；每次上传只解析一次，后续切换统计类型使用内存中的标准化数据。
8. 对大数据量避免在 Vue 模板中执行复杂统计；所有统计先在独立 JS 模块中完成。
9. 不使用 `eval` 或 `new Function`。
10. 不将 Excel 单元格内容作为 HTML 插入页面，必须通过 Vue 插值或 `textContent` 显示，防止恶意单元格内容造成脚本注入。

## 十四、验收标准

AI Agent 完成后，至少需要逐项自测：

### 14.1 上传与读取

- 能分别拖入三个对应文件区域。
- `.xlsx` 和 `.xls` 均能正确读取。
- `.xls` 不依赖 `xlsx.mini.min.js`，必须通过 SheetJS 完整版读取。
- 能识别表头不在第一行的文件。
- 能识别多个工作表，并在多个候选工作表时让用户选择。
- 上传错误类型的文件时有明确提示。
- 替换或移除一个文件，不会误删其他文件的数据。

### 14.2 审核过滤和去重

- 审核状态为数值 3、字符串 3、审核通过的记录保留。
- 其他审核状态不参与报名统计。
- 同一身份证重复行不会重复计数。
- 同一身份证不同报名点能够触发异常，而不是重复计数。
- 空身份证不会被当作同一个有效人员计数。

### 14.3 高考报名统计

- `YSTYSK_` 中 `30|31|41` 能正确拆成三个类别。
- 同一个人多个术科类别可以同时计数。
- 同一个人同一类别重复出现只计 1 次。
- 8 个已知类别列顺序正确。
- 人数、术科人数、特招生测试人数按去重身份证统计。
- 有报名点表和县区汇总表。
- 缺少缴费文件时显示艺术体育可能包含未缴费信息的提示。

### 14.4 高考缴费统计

- 能正确从缴款单号第 18–21 位和第 22–23 位生成报名点代码。
- 边界值 12、13、50、51 的第一位映射正确：12→8、13→9、50→9、51→7。
- 项目编号后缀大小写不敏感。
- `pt/cm/ms/sf/szby/ty/wd/yy` 均能正确归类。
- 同一身份证同一类别重复行不会重复计数。
- 同类别有已缴款及未缴款多行时，按已缴款优先。
- 已缴款计入已缴费，待缴款和未缴款计入未缴费。
- 已缴费列全部排在未缴费列之前。
- 总人数按普通类 `pt` 的去重身份证计算。

### 14.5 交叉比对

- 身份证号码是唯一匹配键。
- 没有任何缴费记录的报名人员按已缴费处理。
- 有缴费记录但普通类未缴款的人员按默认规则不纳入报名总人数及术科人数。
- 普通类已缴款但对应艺术体育类别未缴费时，该类别不计入术科人数。
- 传媒缴费只覆盖播音与主持类（`36`），不能覆盖其他术科类别，也不生成独立“传媒类”术科列。
- 戏曲类省际联考（`39`）只要报名且考生符合总人数纳入规则，就计入人数，不要求任何缴费项目对应。
- `CJTZSCS_` 只有值严格等于 `1` 才计入特招生测试人数。
- 特招生测试人数不因艺术体育某一类别未缴费而被单独误删（但人员必须满足总人数纳入条件）。

### 14.6 1月学选考统计

- 语文和数学有值时只计学考。
- 外语仅在 `KM_YY` 非空时计入。
- 语种代码 1–6 映射正确，0/空白不计入语种列。
- 外语合计包含未知语种人员，未知语种单独提示。
- 政治、历史、地理、物理、化学、生物、技术分别统计学考和选考。
- 所有学考列排在所有选考列之前。
- 同时生成报名点表和县区汇总表。

### 14.7 隐私与使用体验

- 原始 Excel 不会上传服务器。
- 刷新页面后不保留原始个人数据。
- 映射表可持久保存。
- 所有结果是独立 HTML 表格，并有标题。
- 宽表格能够横向滚动。
- 页面没有无效按钮、没有仅用于装饰的控件。
